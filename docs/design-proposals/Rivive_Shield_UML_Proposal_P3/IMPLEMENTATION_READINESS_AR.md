# المسودة التقنية المجمعة وحدود الجاهزية

**جاهزة للمراجعة التقنية والتخطيط، وليست تطبيقًا منفذًا أو دليل قبول متكامل.** القرارات التي وافق عليها المستخدم منفصلة عن الافتراضات التقنية المقترحة. لم تُجرِ خطوة إعداد هذه المراجعة بتاريخ 2026-11-13 تغييرات Git/Trello؛ لا تصف هذه العبارة حالة النشر في وقت لاحق.

## أُغلقت فجوات تصميمية
- سجل الحوادث: طلب صفحة محدود في طابور، تحميل بالخلفية، ونسخة نتائج آمنة للواجهة.
- حفظ الإعدادات: طابور في runtime ونتيجة غير متزامنة؛ لا SQLite أو انتظار في خيط الواجهة.
- ثبات عنوان حالة llhttp: قائمة ذات عناوين ثابتة بدل vector قد يبطل المؤشرات.
- نتيجة إنشاء الحجز: BookingCreateResult يميز الجديد من الطلب المطابق السابق دون استعلام إضافي متسابق.
- أحداث التحكم: نوع صريح للتشخيص وإبطال الخطة واقتراح الإيقاف، دون تهريب الأمر داخل Error.
- جدول انتقالات تقني شامل بأسلوب default-deny؛ كل حالة غير مدعومة مرفوضة، وعدم إغلاق أثر غير محسوم.
- SQL مقترح للحجز والحوادث، مع معرفات فريدة، موافقات ثابتة، طابور تنفيذ محمي بادعاء ذري، وسجل لا يُعاد كتابته.

## نتائج الفحص وحدودها
- C++17 strict syntax وقيود النسخ/الإنشاء ومطابقة header/catalog/SVG: PASS بعد إعادة التوليد؛ لا link أو تشغيل.
- سياسة الحالات: فحص بنيوي للأسماء والحراس ومنع الإغلاق غير المحسوم والتكرار وdefault-deny؛ ليس تنفيذ آلة الحالات الفعلية.
- JSON: تحقق من بنية schema ومثال وتاريخ غير صالح/حقل زائد باستخدام فاحص وقت صريح؛ لا اختبار متصفح.
- SQL الحجوزات: تجاور/تداخل وتراجع صريح في قاعدة ذاكرة مؤقتة؛ لا اختبار توازي أو انهيار لهذا المخطط بعد.
- SQL الحوادث: 18 فحصًا ناجحًا لقاعدة مؤقتة، تشمل active-target unique، claim ذري لا يُستهلك مرتين، rollback، رفض موافقة قديمة/منتهية، ومنع الإغلاق غير المحسوم وثبات التاريخ.

## المتبقي محصور
1. تنفيذ codec البيانات وربط SQL بعقود save/CAS وتخصيص الإصدارات والمعرفات، ثم اختبارات معاملات متزامنة وانهيار قبل/بعد commit. نجاح SQL لا يثبت هذا الربط أو تنفيذ OS مرة واحدة.
2. تنفيذ وربط الكلاسات والمكتبات والواجهة واختبار عمر الموارد وخروج الخيوط وموافقة أول تشغيل. العقد التصريحي لا يتضمن هذه التطبيقات.
3. تثبيت الحدود العددية والإصدارات وسياسة WAL/synchronous وretry كتوصيات تكامل قابلة للقياس؛ لا تُعتبر خيارات المستخدم المعتمدة. إعدادات API الدقيقة والمخططات هنا افتراضات تقنية للمراجعة المجمعة.
4. تشغيل اختبارات Windows على الدمج الفعلي وMac عند أمين؛ لا توريث PASS. إدارة Oracle تحتاج تصميمًا لاحقًا، ولا تمنع تنفيذ النسخة المحلية.

لا حاجة لتعليق كل العمل حتى تُحسم أمور مستقبلية: يمكن بدء الوحدات المحلية بعد مراجعة العقود المجمعة، مع بوابات الاختبار أعلاه. تبقى NeedsReview غير قابلة للإغلاق العام في المقترح الحالي؛ إن احتجنا حسمًا يدويًا آمنًا لاحقًا نضيف له عقدًا واضحًا بدل تجاوز الحظر.
