# ملخص الاعتمادات وحدود المسودة

المستخدم وافق الآن على:
1. موافقة واضحة قبل الإيقاف القسري، ثم فحص SQLite بعد توقف الكتابة، ثم موافقة جديدة قبل التشغيل. التطبيق المتوقف أصلًا لا يُشغّل دون موافقة أيضًا.
2. تأجيل وظيفة إلغاء الحجوزات، مع بقاء منع تداخلها إلزاميًا.
3. نطاق أولي محلي HTTP/1.1 وGET/POST متتابع، واعتبار غير المدعوم غير معلوم، مع اختبار React الحقيقي.

4. حادث فعّال واحد لكل هدف، مع تجميع الملاحظات ومنع الإجراءات المتزامنة وعدم استخدام موافقة قديمة لحادث جديد.
5. عرض الغرف وعرض الحجوزات وإنشاء حجز؛ الطلب نفسه بالمعرف نفسه لا ينشئ حجزًا ثانيًا.

6. فصل قاعدة الحجوزات عن قاعدة الحوادث؛ لا إنشاء بديل صامت عند فقدان قاعدة قائمة أو تلفها، وفحصها بعد توقف جميع الكتّاب.

7. معاملة كتابة واحدة لفحص التداخل وحفظ معرف الطلب ونتيجته ومنع التكرار، مع rollback عند الفشل ورفض المعرف نفسه ببيانات مختلفة، واختبارات التزامن والتوقف.

8. حدود مرنة تجريبية، مع Unknown وتنبيه عند التجاوز أو نقص الأدلة، دون إيقاف تلقائي؛ والمهلة مبنية على القياس لا متوسط عشوائي.

9. الحالات التسع أساس معتمد: Detected وDiagnosing وAwaitingApproval وExecuting وVerifying وRecovered وNeedsReview وDeclined وUnresolved. لا إغلاق لحادث بأثر غير محسوم؛ تفاصيل الانتقالات ما زالت للمراجعة.

10. المسارات GET /api/rooms وGET /api/bookings وPOST /api/bookings معتمدة. JSON ورموز HTTP وتفاصيل الوقت لم تُعتمد ضمن هذه الموافقة.

11. حفظ الوقت بـUTC، وعرضه بتوقيت جهاز العميل، وبداية الحجز قبل نهايته؛ الحجوزات المتجاورة مسموحة. صيغة نقل الوقت الدقيقة ما زالت للمراجعة.

12. نافذة تعرض حالة التطبيق، نشاطًا بلا محتوى الطلبات، الحادث وأدلته وموافقاته وسجل الحوادث؛ المراقبة وقاعدة البيانات بالخلفية، وإغلاق المصحح لا يقتل تطبيق الحجز.

13. التوزيع الكامل والمراجعون وإضافة RS-31 معتمدون كما في `APPROVED_ASSIGNMENTS_AR.md`، وليسوا قرارًا مفتوحًا.

**هذه موافقات على النطاق، وليست اعتمادًا لكل حقول ودوال UML.** عند إعداد هذه المراجعة P3-R2 بتاريخ 2026-11-13 لم تنفذ خطوة إنشاء الحزمة نشرًا إلى Git أو Trello؛ قد تتغير حالة النشر لاحقًا خارج هذه الوثيقة. الحزمة ما زالت مسودة مراجعة موحّدة، ولا نجزّئ التحديثات على المشروع.

الخطوة التالية: `REMAINING_DECISIONS_AR.md` يحتوي توصيات مرتبة لنراجعها تدريجيًا. Mac قيد التحقق، ولا نفترض نجاح اختبارات أمين. Oracle يتطلب تصميمًا لاحقًا مستقلًا للإدارة عن بُعد.
