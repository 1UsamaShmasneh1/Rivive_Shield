## التحويلات الأساسية مقارنة باللوحة الحالية
- RS11 المراقبة: أمين → أسامة، والمراجع شهاب → سامي.
- RS14 واجهة سطح المكتب: شهاب → أمين، والمراجع يزن → شهاب.
- RS24 التخزين: أسامة → أمين، والمراجع سامي → شهاب.
- RS25 القواعد: أسامة بمشاركة شهاب → شهاب، والمراجع سامي → يزن.
- RS31 React: بطاقة جديدة لأسامة، يراجعها سامي. رقم31 في رابط بطاقة المراحل الحالية ليس رقم RS31، ولا يُعاد استخدام بطاقة المراحل للتطوير.

## الأحمال وترتيب التنفيذ
- أسامة: المراقبة والنواة والحالات وReact والدمج والمعمارية وOracle. الحمل الأعلى؛ مهمة أساسية واحدة جارية، ثم التالية. نقل SQLite والقواعد يقلل الحمل لكنه لا يجعله خفيفاً.
- سامي: سيناريوهات وخادم الحجز والتجارب وقواعد الحجز. يتحمل أيضاً مراجعات أسامة، ولذلك تُجدول المراجعات ولا يُفترض توفره المتزامن لكل شيء.
- أمين: SQLite ثم الأدلة ثم GUI، والتوثيق بالتعاون مع الجميع. تكليف واجهة C++ والتخزين معاً كبير، فينفذ متسلسلاً؛ Mac acceptance لا يعد ناجحاً لمجرد إسناد المهمة.
- شهاب: قواعد ثم validation ثم diagnosis، ومراجعة عمل أمين. يمكن إعداد القواعد مبكراً بعد تثبيت العقد.
- يزن: lifecycle/recovery ثم verification/uncertain-stop، وتنسيق اختبارات الفريق وليس كتابتها كلها.

## منع مراجعة النفس
- سامي يراجع أسامة، وأمين يراجع سامي، وشهاب يراجع أمين، ويزن يراجع شهاب، وأسامة يراجع يزن.
- في RS06/20/21/22/28/29/30 متعددة المساهمين لا يكفي مراجع واحد لاعتماد مساهمته الخاصة. يراجع العضو التالي مساهمة الكاتب حسب الدورة.
- RS19 تحديداً: أسامة يراجع يزن؛ سامي يراجع تغيير أسامة للنواة. RS23 مراجع غير الكاتب لكل إصلاح.

## لماذا بطاقة إضافية؟
فصل React عن RS08 يحافظ على مسؤول C++ واضح لسامي ومسؤول واجهة واضح لأسامة ومراجع وتبعيات مستقلة. 30 بطاقة ليست سقفاً وظيفياً؛ وRS31 اعتمدها أسامة صراحة ضمن الخطة. لا نضيف رابطاً قبل إنشاء البطاقة الفعلية. إذا تقرر إبقاء30، البديل قائمتان داخل RS08 بأسماء المسؤولين مع قبول مستقل لكل جزء، لكنه أقل وضوحاً.

## حالة التسليم
هذه ملفات تجهيز لتوزيع معتمد، لكنها ليست بطاقات منشورة أو توزيعاً منفذاً. مطابقة كل شرح عربي بنداً ببند تنتظر القوائم الإنجليزية وعقد P3 النهائي. لا يجوز إعلان اكتمالها قبل ذلك.
