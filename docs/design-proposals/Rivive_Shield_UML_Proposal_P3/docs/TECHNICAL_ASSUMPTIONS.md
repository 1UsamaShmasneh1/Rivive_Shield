# Technical completion assumptions, not additional user decisions

These choices are proposed engineering defaults for review; they do not assert prior approval.

- Wire JSON: `schemas/booking_request.schema.json`; requestId maps to BookingRequest.id; startsAt/endsAt map to UTC interval. Validate real dates, precision/range and start<end in code, not regex alone. Canonical comparisons use parsed values, not JSON textual order. UTC `Z` wire input avoids ambiguous local timestamps; React resolves local input explicitly before conversion.
- Booking SQL: `schemas/booking_proposed.sql`, integer UTC milliseconds, unique request ID, pre-insert overlap trigger as defense in depth, repository BEGIN IMMEDIATE + dedup comparison + INSERT + COMMIT. Identical retry returns the original Booking row/result; conflicting content never overwrites. No automatic migration over an existing DB. This is not the finalized incident schema or journal policy.
- HTTP status proposals remain those in STATE_AND_API_REVIEW_AR.md. Exact codes are not user-approved. All handlers validate input, mask internal errors and bound output. Request format/schema is not the complete list-response pagination contract.
- State table reference is only STATE_AND_API_REVIEW_AR.md. Any unlisted transition is rejected; append-only observations cannot authorize actions. No uncertain side effect may be hidden by closing an incident or creating a replacement.
- Desktop scope is approved. The revised contract includes core.requestHistory + background historyRequests_ + immutable bounded historyPage in OperatorView; settings save queues to ControllerRuntime, executes on the owner thread and publishes async status. Queue acceptance is not storage success. History requests share core capacity; settings queue permits one pending request and returns Busy otherwise. Rendering only reads the published snapshot. No detached lambda or GUI database I/O.
- llhttp state is now stored in stable std::list nodes; parsers are freed before node erase, callbacks cannot outlive nodes. BookingCreateResult carries created flag so proposed new/retry statuses need no race-prone re-query.
- The exhaustive default-deny proposed state policy is schemas/state_policy_proposed.json. It is a technical completion proposal; user approved state meanings, not every transition. No generic dismissal of NeedsReview exists; pending uncertainty cannot be closed. Structural policy checks do not execute application transitions.
- Existing Windows test versions are compatibility evidence. Dependency lock, Mac implementation, target packaging and runtime policies need integration checks; do not install/replace automatically.

- Typed ControlEvent carries BeginDiagnosis, PlanInvalidated or ManualStopProposal; state machine validates which payload and optional plan are legal for each kind. A manual proposal never counts as approval. Error remains an error, not a hidden control channel.
- `schemas/incident_proposed.sql` is a technical storage draft; 18 checks cover unique active incident, immutable approvals/history, guarded dispatch claim and uncertain-outcome closure protection. Codec canonicalization, aggregate version save/CAS and schema migration integration are implementation duties still requiring tests. Claim once is not exactly-once OS execution.
